## 🎨 Стандарт коммитов (Conventional Commits)
Чтобы репозиторий выглядел профессионально, все коммиты пишутся по международному IT-стандарту: `тип: краткое описание на английском`.

### 📌 Основные типы:
* `feat:` — добавлено полностью рабочее решение задачи (зелёный свет на Яндексе)
* `docs:` — создание или изменение файлов `README.md` с описанием условий
* `chore:` — рутинные действия (создание структуры папок, перенос задач в архив)
* `fix:` — исправление багов в коде

### 📝 Шпаргалка готовых коммитов для копирования:
* Настройка структуры: `chore: initialize repository structure and layout`
* Добавление условий: `docs: add README descriptions for solved tasks`
* Сдача Черепашки: `feat: solve yandex-turtle maximum path task via DP`
* Сдача Коня: `feat: solve yandex-knight moves count task via DP`
* Сдача Спелеолога: `feat: solve yandex-cave-3d escape using 3D BFS`
* Сдача Блох: `feat: solve yandex-fleas sum of paths via reverse BFS`
* Уборка в конце недели: `chore: move solved tasks from weekly sprint to archive`
* Шаблон алгоритма: `feat: add pure [algoritm name] algorithm template`

## 🛠️ Главные принципы ведения репозитория
1. **Никакого слепого копирования:** Каждое решение пишется только после полного понимания логики алгоритма.
2. **Чистота портфолио:** Папки и файлы строго структурированы по номерам оригинальных задач на Яндекс.Контесте, чтобы исключить путаницу.
3. **Зелёный свет:** В репозиторий попадают только те скрипты, которые получили официальный статус `Accepted` в тестирующей системе.

## 📈 Как запустить любое решение локально
Для запуска скриптов необходима установленная среда **Node.js**. Перейдите в папку с конкретной задачей и запустите её через терминал, передав входные данные:
```bash
node solution.js < input.txt
```
