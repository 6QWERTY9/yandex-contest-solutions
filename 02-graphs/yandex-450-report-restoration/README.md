# 📈 yandex-450-report-restoration Восстановление отчётов 

## 📝 Условие задачи
Программист Филипп увидел резкое увеличение ошибок в своей программе.

Чтобы понять причины, он принялся изучать отчёты пользователей.

Однако вскоре Филипп заметил, что отчёты фиксируют не все переходы между страницами программы.

Это вызвало у него вопрос: **сколько ещё страниц программы недоступны для анализа по имеющимся отчётам?**


---

## 🎯 Суть алгоритма

1. **Концепция:** Задача решается с помощью построения  графа и его последующего обхода в глубину (DFS), начиная с главной страницы.
2. **Хранение графа (Хэш-таблица):** Поскольку вершины графа — это строки (названия страниц), для списка смежности мы используем обычный JavaScript-объект. Ключом будет название страницы, а значением — массив страниц, в которые есть переход.
3. **Обход (DFS):** Запускаем `dfs`. Алгоритм  посещает все доступные страницы и отмечает их в объекте `visited`.
4. **Финал:** Перебираем изначально заданный список всех страниц программы. Считаем, сколько из них НЕ были отмечены в `visited`. Это количество и выводим в консоль.

---

## 📥 Формат ввода

**Первая строка содержит:** два целых числа: n (1 ≤ n ≤ $10^3$) — количество страниц в программе, m (0 ≤ m $10^6$) - количество записей в отчётах.

**Вторая строка содержит:** n строк, описывающих названия страниц.

**В третьей строке содержится:** одна строка — название главной страницы.

**В следующих m строках:** перечислены записи в отчётах. Запись состоит из двух строк: **первая — страница, с которой ушёл пользователь, и вторая — страница, на которую пользователь перешёл.**



## 📤 Формат вывода

Необходимо вывести количество страниц приложения, до которых невозможно восстановить путь по отчётам.
---

## 💡 Пример
**Входные данные:**
```text
4 3
a b c d
a
a b
b c
a c
```

**Выходные данные:**
```text
1
```
